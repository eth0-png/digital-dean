# Цифровой деканат (концепт)

Прототип личного кабинета студента для конкурса MGIMO AI Challenge, номинация «Вайб-кодинг».

**Это концепт, а не официальный сервис МГИМО. Все данные вымышлены.** Логотип МГИМО не используется.

**Сайт:** https://87.242.100.109.sslip.io (открывается из России без VPN). Тестовые аккаунты: `student1` и `student2` (два студента с разными данными), `dekanat` (сотрудник деканата). Пароли переданы жюри вместе с работой.

## Главная идея: справка как посылка

По опросу студентов справка нужна 11 из 17 обратившихся в деканат, а 10 из 17 решили вопрос только личным визитом. В кабинете студент заказывает справку в пару касаний и видит её путь, как у посылки. Если у деканата есть вопрос, они переписываются прямо в заявке. Готовый документ приходит с QR-кодом, по нему любой проверяет подлинность без входа. Сотрудник деканата ведёт заявки в своём кабинете, а статусы и сообщения у обеих сторон обновляются без перезагрузки страницы.

## Что есть в кабинете

- **Сегодня.** Ближайшая пара и аудитория, то, что требует внимания, пары дня.
- **Расписание.** Неделя и день, свайп по дням, выбор даты в календаре. Изменения и переносы видны на самих парах. На неделях сессии вместо пар показаны зачёты и экзамены. Карточка пары с преподавателем и кафедрой, из неё пару можно добавить в календарь телефона.
- **Учёба.** Курсы и семестры, текущая аттестация, сессия, оценки по 100-балльной шкале с буквой. Шторка «Успеваемость» с графиком по семестрам.
- **Документы.** 4 вида заявок, путь заявки, переписка с деканатом, отмена заявки, справка с QR и открытая страница проверки.
- **Уведомления.** Заявки, изменения в расписании, новые оценки, сроки и объявления деканата.
- **Профиль.** Учебные данные, аватарка из набора значков, кнопка «Нашли ошибку в данных».
- **Кабинет сотрудника.** Очередь заявок, взять в работу, запросить уточнение у студента, выдать справку, согласовать пересдачу, исправить данные, отклонить с причиной.
- **Телефон и компьютер.** Основная ширина 360 px. От 1024 px меню переезжает влево, а экраны делятся на две колонки.

## Безопасность

- Каждая страница и каждое действие проверяют вход и роль на сервере. Данные выбираются по пользователю из сессии, поэтому номер из адреса ничего не открывает, а чужая заявка отвечает «не найдено».
- Пароли хранятся только как хеш bcrypt. Вход ограничен 10 неверными попытками за 15 минут.
- Секреты лежат только в переменных окружения сервера, в коде и в браузере их нет.
- Страница проверки справки показывает только инициалы.

## Стек

Next.js 16 (App Router, TypeScript, Tailwind CSS 4), shadcn/ui на основе Radix, PostgreSQL. Выкладка: Docker Compose на виртуальной машине Cloud.ru, HTTPS через Caddy. Код написал ИИ-ассистент Claude Code, команда ставила задачи, принимала решения и проверяла результат.

## Локальный запуск

Нужны Node.js 24+ и Docker.

```bash
npm install
cp .env.example .env   # раскомментировать DATABASE_URL, задать SEED_PASSWORD_*
npm run db             # PostgreSQL в Docker
npm run dev
```

Тестовые аккаунты `student1`, `student2` (студенты) и `dekanat` (сотрудник) создаются при старте с паролями из `.env`.

Проверка перед коммитом: `npm run check` (линтер, типы, сборка).

## Проверки

Автоматические сценарии в браузере лежат в `scripts/`. Что каждый проверяет, описано в [docs/test-report.md](docs/test-report.md). Все сразу:

```bash
set -a && . ./.env && set +a && node scripts/check-all.mjs http://localhost:3000
```

На боевом адресе идут только сценарии на чтение. Сценарии с записью (`check-flow`, `check-actions`) создают заявки, поэтому запускаются только локально.

## Выкладка на сервер

На машине с Docker и Git:

```bash
git clone https://github.com/eth0-png/digital-dean.git && cd digital-dean
cp .env.example .env   # заполнить DOMAIN, POSTGRES_PASSWORD, SEED_PASSWORD_*
docker compose up -d --build
```

Обновление: `git pull && docker compose up -d --build`. После правки `Caddyfile` ещё `docker compose up -d --force-recreate caddy`.

### Сброс демо-данных для жюри

С `DEMO_RESET=1` в `.env` приложение при каждом старте возвращает заявки, переписку, отметки «прочитано» и аватарки к исходному набору. Даты в демо-заявках считаются от дня сброса, поэтому не устаревают. На сервере приложение перезапускается каждую ночь в 4:00 по Москве:

```bash
0 4 * * * cd ~/digital-dean && docker compose restart app   # строка в crontab, время сервера московское
```

Каждый эксперт жюри видит свежий кабинет, а не следы предыдущего. Заявки, созданные за день, ночью удаляются. Вошедшие пользователи остаются в кабинете.
