# Аудит безопасности

Проведён 10 ноября 2026 ИИ-агентами по навыку `security-audit` от Cloudflare (лицензия MIT, github.com/cloudflare/security-audit-skill), быстрый режим. Все найденные проблемы исправлены в тот же день (коммит `becab73`). Полный отчёт с трассами по коду хранится вне репозитория.

## Как проходил

Аудит вёл один координирующий агент, который раздавал работу другим и сам ничего не искал. Агенты только читали исходный код: не запускали проект, не обращались к сети и к боевому сайту, файл `.env` не открывали.

| Этап | Агенты | Модель | Что делали |
|---|---|---|---|
| Разведка | 4 | Claude Sonnet 5.5 | Составили карту: роли, все серверные действия и их проверки доступа, входы данных, устройство выкладки |
| Поиск | 13 | Claude Fable 5.2 | Каждый получил свой участок и искал нарушение одной конкретной границы. Друг друга не видели |
| Критик покрытия | 1 | Claude Fable 5.2 | Проверил, какие участки остались без внимания |
| Перепроверка | 7 | Claude Opus 5.5 | Каждую находку перечитал свежий агент на другой модели с задачей её опровергнуть |

Всего 25 запусков при потолке 30. Седьмой проверяющий понадобился, потому что один вернул испорченный результат: по правилам навыка такой результат не чинят, а отбрасывают и перепроверяют заново.

Участки поиска: сессии и подделка запросов, заголовки от прокси, действия студента, действия сотрудника, чтение чужих данных, проверка справки по QR, инъекции, логика статусов заявки, секреты и история репозитория, выкладка, кеширование личных страниц, нагрузка, всё вне категорий.

После агентов координатор сам проверил каждую находку запуском на локальной копии с демо-данными, а после исправления проверил ещё раз.

## Что подтвердилось как сделанное правильно

- Каждое серверное действие и каждая страница проверяют сессию и роль на сервере. Роль читается из базы на каждый запрос.
- Запросы студента привязаны к пользователю из сессии. Чужая заявка неотличима от несуществующей.
- SQL везде параметризован. Пользовательский текст выводится только через экранирование React.
- Секретов нет ни в коде, ни в истории репозитория (78 коммитов).
- Защита серверных действий от подделки запросов работает и ничем не ослаблена.
- Личные данные не попадают в общие заготовки страниц и в кеш.
- Наружу опубликован только обратный прокси, порт 80 перенаправляет на HTTPS.
- Смена статуса заявки одним запросом с условием на текущий статус: одновременные действия студента и сотрудника не дают двойного перехода.

Способа увидеть или изменить чужие данные агенты не нашли.

## Что нашли и как исправили

| Находка | Что было | Что сделали |
|---|---|---|
| Сессии переживали смену пароля | После смены пароля аккаунта уже открытые сессии работали до 30 дней | При старте сервер сравнивает новый пароль с прежним хешем и, если он изменился, завершает сессии этого аккаунта |
| Cookie сессии не была привязана к хосту | Чужой сайт на общем домене `sslip.io` мог подложить нашему сайту свою cookie, и сервер брал её | Cookie называется `__Host-session`: браузер принимает такую только от самого хоста |
| ФИО в старых ссылках проверки | Страница проверки справки брала ФИО из текущего профиля. После исправления ФИО старая ссылка показывала новую фамилию | ФИО запоминается в момент выдачи справки. Справка и проверка по QR показывают его |
| Гонка в лимите входа | Попытка записывалась после проверки пароля, одновременные запросы проходили сверх лимита | Попытка записывается до проверки. Одновременно сравнивается не больше четырёх паролей |
| Блокировка входа с общего адреса | Десять ошибок с одного адреса закрывали вход всем с этого адреса | Лимит считается по паре «адрес и логин». Чужие ошибки не закрывают вход в другой аккаунт |
| Заявки без ограничения | Студент мог создавать заявки без предела. Очередь деканата грузила все заявки разом и на 65534 заявках падала | Предел 20 открытых заявок и 100 новых за сутки на студента. В очереди все открытые и 200 последних закрытых |

Проверка до и после на локальной копии:

| Находка | До | После |
|---|---|---|
| Сессии | Старая сессия сотрудника открывала очередь после смены пароля | Сессия завершена, сессии других аккаунтов не тронуты |
| ФИО | «Петров И. С.» превращался в «Тестов О. Ю.» | Остаётся «Петров И. С.» |
| Лимит входа | Залп из 20 попыток: 12 записей при лимите 10 | Залп из 20 попыток: 8 записей |
| Очередь | 5000 заявок: 8 с. 65534: ошибка | 70000 закрытых и 5000 открытых: 1,3 с |

Заодно исправили мелочи, которые не были уязвимостями:
- три действия сотрудника проверяли текст раньше роли, теперь роль первой строкой;
- шапка кабинета сотрудника отдавалась до проверки роли, теперь после;
- вид документа из служебных имён (`constructor`) давал ошибку сервера, теперь «не найдено»;
- номер заявки из запроса принимается только строкой;
- адрес для QR-кода строится только из разрешённых хостов;
- инструмент `shadcn` перенесён в зависимости для разработки, `npm audit --omit=dev` без замечаний.

## Сверка со справочниками OWASP

Сверены три справочника OWASP Cheat Sheet Series: Authentication, Session Management, Password Storage. До исправлений не выполнялись два пункта из пятнадцати (префикс `__Host-` у cookie и завершение сессий при смене пароля) и частично один (защита от перебора). После исправлений остаётся одно осознанное отступление: срок жизни сессии 30 дней без срока бездействия. Он выбран по опросу, где вход с телефона назван главной трудностью.

## Что осталось за рамками

- Быстрый режим навыка даёт частичное покрытие: одна волна поиска.
- Критик назвал два участка, которые агенты не проверяли: встраивание страниц в чужой сайт и поведение порта 80. Координатор проверил их запросами к сайту: заголовки запрета встраивания есть на всех видах ответов, порт 80 перенаправляет на HTTPS.
- Сам сервер, его брандмауэр и значения в `.env` в аудит не входили.
- Открытая очередь деканата не разбита на страницы. При тысячах открытых заявок это станет заметно, для прототипа с тремя аккаунтами не нужно.

## Что новые проверки ловят теперь

- `check-access`: cookie сессии называется `__Host-session`, в ответе на `/staff` для студента нет шапки кабинета сотрудника.
- `check-flow`: в уже выданной справке после исправления ФИО остаётся прежнее ФИО.
- `check-actions`: предел открытых заявок, вид документа из служебных имён, вход в другой аккаунт во время блокировки, залп из 20 одновременных входов не проходит сверх лимита.
